# 硬件要求与引擎选择

以下数字在 RTX 4090 参考机上实测，单 worker 稳态显存。控制台「本地服务」会按你的显卡重新算容量，这里是下限。

| 档位 | 数字人引擎 | 显存 | 能跑的卡 |
|---|---|---|---|
| 最省 | wav2lipLS（384）≈ 2 GB + 语音识别 1.4 GB，EdgeTTS 不占 | ≈ 3.5 GB | 任何 6 GB 显卡 |
| 画质 | FlashHead ≈ 6.6 GB 或 MuseTalk 1.5 ≈ 7.7 GB，+ 语音识别 | ≈ 8–9 GB | 12 GB 显卡，一路实时 |
| 并发池 | 2 × MuseTalk + 语音识别 | ≈ 17 GB | 24 GB 显卡，2–3 路 |
| 没有显卡 | 远端数字人 worker + 云端 LLM/TTS | 0 | 笔记本 / 云主机只跑 cored 和控制台 |

怎么选：wav2lipLS 最便宜也最糙；MuseTalk 对任意素材最鲁棒；FlashHead 只要一张肖像不用烘焙，但是 512² 头肩范式。

## 响应速度（实测）

公开演示机，单张 RTX 4090，Qwen 实时大脑，2026-10-11。"判停"指轮次检测确认访客说完的时刻。

| 指标 | MuseTalk 1.5（512） | FlashHead 半身（720×1280） |
|---|---|---|
| 判停 → 大脑首包回复音频 | 1–170 ms | 1–170 ms |
| 判停 → 引擎输出第一段口型音频 | 0.40–0.72 s | 0.86–1.15 s |
| 引擎：音频到达 → 首帧（其中计算） | 0.32–0.55 s（0.24–0.48 s） | 0.79–0.90 s（0.62–0.76 s） |
| 本地大脑（LLM + EdgeTTS）：请求 → 首包音频 / 首帧 | 0.37–0.52 s / 0.73–1.07 s | — |
| 本能层决策：Jev 经代理 / 本地规则 | 0.4–0.85 s / 0 ms | 相同 |
| 访客丢包 → 关键帧（PLI 转发） | ≤ 0.5 s | ≤ 0.5 s |

经验法则：FlashHead 的首帧比首包音频晚约 1 秒、MuseTalk 约 0.5 秒，所以音频闸门会把最初几包压到视频就绪再放（从第 0 帧起就对口型）。待机完全不占 GPU；每路会话的持续开销只有说话时的引擎。
